# Academic Planning Output Taxonomy And Visual Master

Use this reference whenever the user asks to define, classify, redesign or standardize 学业规划 outputs, especially when they mention T01, T02, T03, standard plans, custom plans, mixed DP plans or quote sheets.

## Canonical Visual Master

The default customer-facing planning style is the UCL-style project-management layout:

- A4 portrait pages, white background, a thin blue-cyan gradient strip at the top and restrained brand accents.
- Full horizontal logo on the cover or first page; use IP only as a supporting closing/cover visual and keep it unobstructed.
- One page solves one question. Avoid repeating the same service explanation across course-risk pages.
- Use a large blue-gradient title block on cover pages, three metric cards for targets/hour counts, deep-blue table headers, pale-blue alternating table rows, mint cards for positive/DP modules and amber boxes for boundaries or pending materials.
- Prefer tables for dense course/service mapping, DP workload, quote detail and responsibility allocation. Use cards only for targets, process steps and short support modules.
- Keep copy client-facing and concrete. Do not include internal audit traces, private pricing mechanics, endpoint names, model-estimate labels or contrastive sales copy.

This visual master supersedes the older free-form card-heavy customer proposal style. The SIM DIT style remains a usable variant for pure 新生首年陪跑 proposals, but mixed DP/exam/support proposals should prefer the UCL structure.

## Output Families

### Standard Academic Plan

Use when the user asks for 标准方案、标准全年规划、T01 or a normal academic-planning proposal without custom price or DP complexity.

Suggested structure:

1. Cover: school, programme, year, target range, total lessons or package signal.
2. 学情判断与全年目标: current basis, year risk, target tiers and target boundary.
3. 课程考核与服务路径: all courses in one table with assessment, service path and management focus.
4. 课时结构与阶段安排: standard package hours, professional/pacing split and term timeline.
5. AI智慧学习系统与过程沉淀: course archive, weak points, weekly record and exam review pack.
6. 执行责任与启动资料: roles, student responsibilities and pending materials.

No price appears unless the user requests a quote.

### Custom Academic Plan

Use when the user asks for 定制方案、自定义课时、轻陪跑、重点非重点组合 or a tailored support mix.

Suggested structure:

1. Cover with the custom configuration as a clear first-screen signal.
2. 学情判断与目标: explain why the custom mix is appropriate.
3. 课程分层总表: mark 重点/非重点/缓冲/出勤 courses and service path.
4. 课时配置: show per-course professional lessons and pacing lessons; enforce user-stated caps.
5. 高风险课程执行法: compress risk handling into one table instead of many repeated cards.
6. 全年推进与调整节点.
7. 执行责任、学生配合和正式启动材料.

Professional lessons should dominate when the student needs exam/content support. If the user says 陪跑课每门2-3节, keep every course within that cap.

### Mixed DP + Planning Plan

Use when the user asks for DP加陪跑、DP安心包与考试陪跑、混合方案 or a plan combining DP with academic support.

Suggested structure:

1. Cover: DP + exam/support dual path, number of DP modules, number of exam/support courses, target ranges and lessons.
2. 学情判断与全年目标: separate DP target, exam/support target and overall target; include a concise target boundary.
3. 课程考核与服务路径: one table for all courses, with `DP完整`, `DP轻量`, `重点考试陪跑`, `轻陪跑` or equivalent service labels.
4. DP工作量与执行流程: DP-supported assessments, assessment type, service depth, management content and the six-step DP path.
5. 考试/专业课支持: course-level professional lessons, pacing lessons and expected outputs.
6. 校历节点与排课策略: before term, weeks 1-4, term progress, exam countdown and post-result review.
7. 执行责任与配合边界: project manager, planner, professional teacher team, DP team, quality review, AI system and student responsibilities.
8. 预期效果与正式执行条件: process outcomes, target ranges, materials needed and formal execution basis.

Keep DP, professional lessons and pacing lessons as separate service layers. DP must not imply coverage for exams, attendance, online tests or ordinary course learning unless explicitly scoped.

### Planning Quote Sheet

Use when the user asks for T03、陪跑报价、标准报价、定制报价 or a standalone planning quote.

Suggested structure:

1. Quote title and student/program context.
2. Three large price cards: professional/pacing subtotal, discount or package status, final total.
3. Quote detail table: course/service line,重点/非重点 classification, subject type, professional direction, professional lessons, pacing lessons, matched service, original price, discount and final price.
4. Component service table: included component services and each component's approved unit amount; in custom plans components are counted once by default unless the user explicitly says otherwise.
5. Quote quick-reference table: standard course-count discounts and重点/非重点 combinations, with original price, discount/saving and discounted price.
6. Validity, material boundary and scope note.

Do not include DP pricing in a planning-only quote. For mixed products, show a separate DP quote block produced by the DP quote route.

Calculation principle:

- Standard quote: first count key/non-key courses, then match the approved quick-reference matrix. If matched, display the exact catalog row's original price, discount/saving and discounted package price.
- Custom quote: use the current student's course lines, custom lesson counts, subject type and professional direction to read unit prices from the authorized pricing source, calculate each course, count component services once by default, apply approved discount rules and display original total, discount status and final total.
- Mixed quote: calculate planning and DP independently, then add approved subtotals only at the display layer. When DP is included, show which courses matched DP and the single-course DP price when the DP quote source returns it.
- Unmatched matrix, missing private pricing source or conflicting quote logic: show `待内部核价`, `待确认折扣` or a clear `预警提示`; do not reuse another student's price.

### Public-Sector Concise Plan

Use when the user asks for T02、对公精简方案 or a brief service-match plan.

Suggested structure:

1. One-page or concise multi-section page using the same UCL visual language.
2. Basic context, compact assessment summary, service-match table, stage timeline, AI learning system role and expected effect.
3. No long sales copy, no private pricing and no internal warnings.

## Content Rules Across All Families

- Show course/service matching as a concrete table whenever there are more than four courses.
- State targets as reasonable ranges: 稳妥目标、主目标、冲刺目标 or equivalent.
- Do not promise guaranteed grades, guaranteed passing or unconditional refunds in the proposal body.
- Use the phrase `正式执行以学校handbook、课程平台、Assessment Brief、个人课表和考试安排为准` or an equivalent boundary when official materials are incomplete.
- Quote artifacts may show authorized final prices, but never expose private formula, API endpoint, secret, raw trace or internal review mechanics.
