# DP Proposal Patterns

Use this reference after `SKILL.md` triggers and the task requires a client-facing DP proposal.

## Core Design Idea

A strong DP proposal sells managed academic outcomes, not isolated writing help. It should make the customer feel:

- The course structure has been studied.
- The score target has been translated into a concrete risk map.
- Each module has a service plan, not generic “teacher support”.
- DP is justified by workload, assessment risk, target pressure, capstone/dissertation weight, or weak student baseline.
- The service has process visibility, quality control, team roles, and feedback loops.

## Useful Page Modules

### Cover
Include:
- Product status: `DP安心包`, `DP卓越安心包`, or `毕业无忧`.
- Do not show internal/publication labels such as `官网检索版`, `报价确认版`, `客户发送版`, or `样例模板` on the client cover. Keep those labels in the file name or internal notes only when needed.
- School + programme + year/term.
- Target score: `60+`, `65+`, `Distinction`, `Merit`, `毕业稳过线` as applicable.
- 3-4 number cards: credits, course count, capstone/dissertation weight, quote if approved.

### Client Situation And Conclusion
Summarize the student in 2-4 sentences:
- Current baseline or risk.
- Course/assessment structure.
- Why single-assignment support is insufficient.
- Recommended DP product.

Example positioning:
`这不是单篇 essay 问题，而是三学期/全年权重、DDL 和质量标准的项目制管理问题。`

### Official Course Structure
Build a table:
`类别/学期 | 模块 | Credits/UOC/CATS | 官方口径/考核结构 | 目标分风险判断`

Good assessment language:
- `官网显示 ...`
- `官方 Course Outline 显示 ...`
- `按客户提供的 brief / 选课资料 ...`
- `最新权重需以 Moodle / Blackboard / Course Outline 为准`

Do not invent exact weights. If only course descriptions are public, write course aims and risk, then mark assessment as pending confirmation.

### Workload Estimate
Use only when useful for pricing/value justification.

Common fields:
`模块 | 主要交付物 | 预估等效工作量 | 管理重点`

Estimate by assessment type:
- 15-credit/CATS/UOC essay/report course: often 3,000-5,500 words equivalent depending on presentations/quizzes.
- Dissertation/project/capstone: estimate separately and prioritize by credit weight.
- Presentations count as equivalent workload because they need slides, script, Q&A, group coordination, and rehearsal.

Always label estimates as proposal-stage planning numbers.

### Target-Score Management
Create a page or block named after the goal:
- `65分目标管理`
- `Distinction目标管理`
- `60+稳分管理`

Include 3-5 reasons:
- High-weight capstone/dissertation/project must start early.
- Pure essay/report courses can stabilize output if topic and rubric are locked early.
- Presentation/group work needs slide/script/Q&A management.
- Exam/quiz modules need separate revision frameworks.
- Methods/data/statistics modules can affect dissertation/project quality.

### Why DP
Explain in business terms:
- DP manages the whole period, not one assignment.
- DP creates one project board for modules, briefs, rubrics, DDLs, scores, and feedback.
- DP protects high-credit or high-weight items first.
- DP matches multiple roles: project manager, academic planner, subject teacher, quality reviewer.

Avoid exaggerated phrases. Say `降低风险`, not `消除风险`.

## DP Service Content Blocks

### What We Provide
Use concrete bullets:
- Course archive: modules, briefs, rubrics, DDLs, reading lists, feedback.
- Task cards: scoring points, structure, literature/cases/data, deliverables, risk.
- Outline-first workflow: confirm argument and rubric alignment before full draft.
- Quality review: structure, evidence, citations, language, format, originality-risk review.
- Progress transparency: outline, draft, 70%, final, submission, feedback.
- Feedback optimization: adjust next tasks based on tutor feedback and grades.

### Minimum Service Safeguards
Use careful language:
- `按合同约定的服务范围和DDL推进`.
- `每项任务进入大纲、初稿、质检、终稿复核节点`.
- `未达到内部质量线的内容进入返修`.
- `客户收到导师反馈后，服务期内按约定范围协助分析和修改`.
- `保障以合同条款为准，不做绝对分数或学校结果承诺`.

### Team Configuration
Common roles:
- Project manager: schedule, DDL warnings, materials, progress, client communication.
- Academic planning teacher: course selection, target-score plan, priorities.
- Subject teacher group: programme-specific expertise.
- Methods/dissertation/capstone teacher: proposal, methods, data, chapters.
- QC delivery team: rubric alignment, citations, language, format, originality-risk review.

### Process Flow
Macro 8-step flow:
1. Sign-off and team matching.
2. Archive setup.
3. 24h student/risk diagnosis.
4. 72h term/year plan.
5. Milestone execution.
6. Multi-layer quality review.
7. Feedback and strategy update.
8. Closing review and next-step planning.

Single-assignment 6-step flow:
1. Collect course materials.
2. Generate task card.
3. Outline stage.
4. Draft/full production or guided development.
5. Quality review and revision.
6. Final check and delivery note.

## Course-By-Course Planning Table

For a focused term plan, use:
`课程 | 课程内容与考核口径 | 主要难点 | 风险 | 我们提供的服务`

For each course, make the service concrete:
- Essay/report: topic, thesis, outline, evidence, rubric, citations, final quality check.
- Presentation/video: slides, speaker notes, script, timing, Q&A, group division.
- Quiz/exam: weekly revision table, concepts, worked examples, timed practice.
- Participation/seminar engagement: weekly speaking points, attendance/engagement evidence, short written responses.
- Capstone/dissertation: topic, proposal, literature, method, data/materials, chapter plan, final polish.

## Quote Handling

Include quote only if the user asks or enough price direction exists.

If the user explicitly asks for DP报价/价格/报价单, read `dp_pricing_rules.md` before answering. Do not stop just because exact DP price files are missing; create an internal quote draft with `待价格文件核对` and clear included/excluded scope.

Client-facing quote page:
- Product name.
- Payment mode: one-off / staged / account recharge.
- Final price or quote status.
- Scope covered.
- Conditions that may require re-quote.

Never expose:
- Internal quote formula.
- Bottom line.
- Margin.
- Negotiation room.
- Internal “why this price” calculation.

For internal quote drafts, the formula and pricing status may be shown, but keep it outside any client-facing PDF and mark it `内部报价版`.

If the user asks to remove price, remove all occurrences of:
`报价`, `预算`, `¥`, numeric price strings, `万人民币`, and quote-status blocks.

## Visual Style

Use a clean consulting style:
- Strong first page with school/program/product signal.
- Dense but readable tables.
- 8px-radius cards.
- Blue/cyan, navy/teal, or school-adapted palette.
- No childish decorations.
- No nested cards.
- Use tables for official course structure and service scope.
- Use process cards/timelines for DP service value.

## Quality Checklist

Before delivery:
- Course list matches user-provided final selection.
- Official and inferred assessment data are clearly separated.
- Client PDF contains no internal memo or hidden pricing notes.
- No absolute grade guarantee appears.
- Target score language is framed as risk management.
- Quote is present only when requested.
- Filenames follow user naming rules.
- PDF is valid, readable in Chinese, and not blank.
